يبدو التوليد الثابت المتزايد ISR إعدادًا آمنًا: ابنِ الصفحة مرة، ثم حدّثها دوريًا كي لا تصبح قديمة. يناسب ذلك مصدرًا يستطيع التغير من دون نشر جديد.

لكن مصدر PitchIQ لم يكن يستطيع ذلك. بيانات كرة القدم التاريخية ملفات JSON ملتزم بها داخل المستودع. يصل تحديثها عبر Pull Request، ودمجه يطلق نشرًا يعيد بناء الصفحات أصلًا. لم يستطع المؤقت اكتشاف معلومة جديدة، لكنه نفّذ العمل كاملًا.

## العرض بدا كاستهلاك طبيعي للمنصة

أظهرت صفحة Functions في Vercel أن المسارات التاريخية تستهلك **٣٫٦–٥٫٠ ثوانٍ من Active CPU**. وصل مسار Legacy إلى **٤٫٩٧ ثانية** للاستدعاء، ومسار منافس إلى **٤٫٩١ ثانية**.

تقرأ هذه المسارات ٣٤ موسمًا لإعادة بناء تاريخ النادي. هذا مقبول وقت البناء ومكلف عندما يتكرر عبر **٥١ ناديًا × لغتين**.

## الإعداد صنع تضخيمًا في الكتابة

كان المسار يحمل نافذة إعادة توليد موجبة:

```ts
// أعد بناء الصفحة بعد يوم واحد.
export const revalidate = 86_400;
```

بعد انتهاء النافذة، أعاد الطلب التالي توليد الصفحة وخزّن ملفًا بديلًا. كان الناتج مطابقًا لأن JSON داخل النشر لم يتغير.

```text
توليد صفحة مكلف
× ٥١ ناديًا
× لغتين
× كل نافذة إعادة توليد
= CPU وكتابات متكررة من دون محتوى جديد
```

هذا هو تضخيم الكتابة: سياسة تخزين صغيرة تكرر الحساب والتخزين عبر مصفوفة كبيرة من المسارات الثابتة.

## لماذا لم تكفِ المحاولات الأولى؟

خفّض تخزين المحمّلات وتحسين التحويلات تكلفة التصيير الواحد، لكنه لم يلغِ تكراره. وزيادة المدة جعلت الهدر أقل تكرارًا فقط.

كما أن البحث عن الرقم المعروف لم يكن آمنًا. البحث عن `86400` فاته ثلاثة مسارات تستخدم `revalidate = 60`. القاعدة الحقيقية هي منع كل قيمة موجبة، لا منع رقم بعينه.

## اجعل عمر التخزين مطابقًا لعمر البيانات

تبقى صفحات البيانات الملتزم بها مخزنة حتى النشر التالي:

```ts
// JSON داخل النشر ثابت؛ النشر الجديد هو حدث الإبطال.
export const revalidate = false;
```

وهذا يختلف عمدًا عن الصفر:

```ts
// نقطة نهاية تعمل عند الطلب ولا يجب تخزينها.
export const revalidate = 0;
```

تعني `false` بقاء الناتج الثابت طوال عمر النشر، بينما يعطّل `0` التخزين. الخلط بينهما يحول إصلاح التخزين إلى انحدار CPU عند كل طلب.

تستخدم الحالات الاستثنائية وسمًا محميًا بدل مؤقت شامل:

```ts
import { revalidateTag } from 'next/cache';

export async function GET(request: Request) {
  const url = new URL(request.url);

  if (url.searchParams.get('secret') !== process.env.REVALIDATE_SECRET) {
    return new Response('Unauthorized', { status: 401 });
  }

  revalidateTag(url.searchParams.get('tag') ?? 'football-data');
  return Response.json({ revalidated: true });
}
```

## حوّل القرار المعماري إلى قاعدة قابلة للتنفيذ

يفحص اختبار الانحدار ملفات المسارات ويرفض القيم الموجبة مع السماح بـ`false` وبنقاط النهاية المقصودة التي تستخدم `0`:

```ts
const match = source.match(/export const revalidate\s*=\s*(\d+)/);

if (match && Number(match[1]) > 0) {
  throw new Error(`${route}: committed data must not use timed ISR`);
}
```

هذا أقوى من قائمة مدد ممنوعة، لأنه يصف العقد الحقيقي للنظام.

## القاعدة الأوسع

- إذا كانت البيانات تتغير فقط أثناء النشر، فولّدها أثناء النشر.
- إذا كانت تتغير بصورة مستقلة، فاستخدم الوسوم أو الأحداث أو مدة لها مبرر واضح.
- قِس عدد المسارات واللغات وتكلفة إعادة التوليد معًا.
