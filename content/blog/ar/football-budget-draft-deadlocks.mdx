بدا Budget Cap ميزة واجهة: ضع سعرًا على البطاقة وامنع الإنفاق فوق €١٠٠M. لكنه كان محلل قيود يجمع اقتصاد العصور والأيدي العشوائية والاستبدال وحساب الأرقام.

## كان pool ممكنًا لكن اللعبة الموزعة لم تكن

كلف أرخص XI في pool نحو €٤٦M، فبدا الحد آمنًا. لكن اللاعب يختار من خمس بطاقات عشوائية لكل خانة. في التوزيع الحقيقي وصل مجموع أرخص بطاقة في كل يد إلى **€١٣٧M–€٢٦٥M**. تعطلت كل البطاقات قبل الاختيار الأول.

قاس الفحص الخطأ حد pool، بينما تحد اللعبة الأيدي التي تعرضها.

```ts
function deal(slot: Slot, eligible: Card[], rng: RNG) {
  const cheapest = minBy(eligible, price);
  return unique([cheapest, ...seededSample(eligible, 4, rng)]);
}
```

خفض ضمان أرخص بطاقة مؤهلة في كل يد الحد إلى €٤٧M–€٥٠M. أخفت fixtures اليدوية العيب لأنها وضعت بطاقة رخيصة في كل يد أصلًا.

## احتاجت الأسعار التاريخية إلى فهرسة ثم عملة لعبة

جعلت القيم الخام العصور القديمة الخيار المنطقي الوحيد. كما كانت فهرسة الوسيط خاطئة: تضخم وسط السوق نحو ٦٫٥× بينما تضخمت القمة ٤٫٣×، فصار نجم ٢٠٠٤ بسعر €١٧٩M مقابل لاعب مشابه في ٢٠٢٤ بسعر €١٠١M.

ثبّت PitchIQ عوامل أعلى ٥٠ لاعبًا، ثم استخدم القيمة الحقيقية للترتيب فقط:

```ts
function gamePrice(percentile: number) {
  const millions = 4 + 15.5 * percentile ** 2;
  return Math.round(millions * 10); // أعشار صحيحة من £1M
}
```

تحافظ النسبة المئوية على الصفقات—اختلاف ترتيب الجودة عن السعر—من دون بطاقة £١٠٤M تحت سقف £١٠٠M. فشل القياس الخطي لأن انحراف السوق ضغط نحو ٩٠٪ من البطاقات داخل نطاق ضيق.

## ضغط الأسعار غيّر الصعوبة أيضًا

سمح ضغط نطاق ٤٠× إلى ٤٫٩× بشراء **٩٧٪ من أفضل XI ممكن**. رفع حجم pool ثلاثة أضعاف النتيجة إلى ٩٥٫٢٪ فقط مع حمولة أكبر. الأس هو أداة الصعوبة لا العمق.

يقيس كل تغيير:

- تكلفة XI المثالي؛
- الجودة الممكنة تحت السقف؛
- التوزيع الذي يراه شخص يختار من خمس بطاقات؛
- الإمكانية عبر كل التشكيلات.

## المال العشري صنع قرارات غير مستقرة

يجمع الاحتياطي عشرة أسعار مستقبلية في كل render. قد يجعل انحراف floating point البطاقة متاحة مرة وممنوعة بعدها. لذلك تستخدم الأسعار أعشارًا صحيحة:

```ts
type PriceTenths = number;

const spent = squad.reduce((sum, card) => sum + card.priceTenths, 0);
const canAfford = spent + candidate.priceTenths + reserve <= capTenths;
```

## استبدال اللاعب حبس الشاشة

عند فتح خانة ممتلئة، أضاف الحساب القديم اللاعب إلى `spent` وحد اليد إلى `reserve`. لم ير المدرب إلا الباقي، وتعطلت البدائل، ولم يملك modal الموروث إغلاقًا أو Escape.

يجب ألا تسهم الخانة المفتوحة في الرقمين:

```ts
for (const [index, pick] of picks.entries()) {
  if (index === openSlot) continue;
  if (pick) spent += priceOf(pick);
  else reserve += cheapestFor(index);
}
```

تسمح الحزم القابلة للمراجعة بالإغلاق أو إخلاء الخانة، وتبقى الحزم المقفلة غير قابلة للإغلاق. يُشتق السلوك من `lockPicks` لا اسم الوضع.

## خانة الدكة ليست خانة تشكيل

انهارت خانة ١٢ عند `shape.slots[i].role` لأن التشكيل يملك ١١ لاعبًا. يملك resolver واحد الحد الآن:

```ts
function roleAt(index: number, shape: Formation): Role {
  return shape.slots[index]?.role ?? BENCH_ROLES[index - shape.slots.length];
}
```

## يجب أن تمثل الاختبارات الإنتاج

عرّفت fixture الخاصة بالوضع `lockPicks: true` بينما الحزمة الفعلية `false`، فاختبرت ١٢٦ حالة مسارًا لا يحدث. تستورد الاختبارات الحزمة الآن، وتستخدم بيانات حقيقية، وتفتح خانة ١٢، وتفحص طرق الخروج.

تحتاج اللعبة المقيدة إلى برهان لكل حالة يستطيع اللاعب بلوغها، لا لتشكيلة نهائية صحيحة فقط.
