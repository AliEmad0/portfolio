ثلاث مشكلات في Next.js 16 كلفتني كل واحدة منها فترة بعد ظهر كاملة. وكانت كل واحدة موضحة في جملة واحدة داخل توثيق لم أقرأه.

## Turbopack لا يشغّل Middleware أثناء التطوير

يحوّل الموقع المسار `/` إلى `/en` باستخدام Middleware. لكن أثناء تشغيل `next dev` كان المسار `/` يعيد صفحة 404 محليًا فقط، بينما كان الإنتاج يعمل بصورة صحيحة.

خادم التطوير في Turbopack لا يشغّل Middleware. لذلك لا يظهر أي منطق للتدويل أو التوجيه موجود هناك قبل تنفيذ بناء إنتاجي:

```bash
next build && next start -p 3112
curl -sD - localhost:3112/
```

إذا تعذر التحقق من تغيير في التوجيه أثناء التطوير، فتحقق منه باستخدام بناء إنتاجي. دائمًا.

## صور OG الثابتة تتعطل داخل مسار ديناميكي

وضعت `opengraph-image.png` داخل `app/[locale]/`. نجح البناء محليًا وفي CI، ثم فشل النشر على Vercel:

```
Error: Invariant: failed to find source route /[locale]/opengraph-image.png
```

كان الاختلاف أن Vercel استعاد ذاكرة بناء مؤقتة تعود إلى ما قبل وجود هذه المسارات. وضع صورة بيانات وصفية ثابتة أسفل مسار ديناميكي يكون هشًا في هذه الحالة.

كان الحل التوقف عن استخدام اصطلاح الملف في ذلك الموضع، ووضع الصورة في `public/og.png` والإشارة إليها بوضوح:

```ts
const ogImage = { url: '/og.png', width: 1200, height: 630, alt: title };
return {
  metadataBase: new URL(siteUrl),
  openGraph: { images: [ogImage] },
  twitter: { card: 'summary_large_image', images: [ogImage] },
};
```

عند ضبط `metadataBase` يتحول المسار النسبي إلى عنوان مطلق، ولا يمكن أن يعود خطأ invariant.

## صورة OG في جذر التطبيق لا تصل إلى مسار اللغة

من المفيد معرفة ذلك قبل محاولة «إصلاح» المشكلة السابقة بنقل الملف إلى الأعلى: ملف `opengraph-image.png` في جذر التطبيق لا يُرفق بمسارات `/[locale]`. تختفي الوسوم بصمت، دون خطأ أو تحذير، ولا تلاحظ المشكلة إلا عندما تظهر معاينة الرابط فارغة.

افحص HTML الناتج بدلًا من الاعتماد على الافتراضات:

```bash
curl -s localhost:3112/en | grep 'og:image'
```

## النمط المتكرر

نجحت كل هذه الحالات محليًا ونجحت في CI. لم يظهر الفشل إلا مع ذاكرة مؤقتة دافئة، أو نطاق حقيقي، أو بناء إنتاجي. ثق في نتيجة النشر، لا في خادم التطوير.
