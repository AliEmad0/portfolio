كان لدى PitchIQ آلاف الصفحات المولّدة مسبقًا، ولا توجد قاعدة بيانات تعمل وقت الطلب، وزمن التصيير جيد. ومع ذلك سجّل ٣٩ ألف استدعاء للدوال خلال اثنتي عشرة ساعة.

كانت الصفحات ثابتة، لكن الاستجابات لم تكن قابلة للتخزين المؤقت.

## الدليل كان في الترويسات

كان كل مسار HTML يعيد Set-Cookie: NEXT_LOCALE. لا تستطيع شبكة CDN مشتركة تخزين استجابة تغيّر ملف ارتباط للزائر، لذلك أعاد Vercel:

```text
x-vercel-cache: MISS
cache-control: private, no-cache, no-store
```

أما robots.txt والصور التي لا تمر عبر Middleware فكانت تعيد HIT. هذه المقارنة حدّدت السبب قبل أي تحليل أداء.

## حسّنا الرقم الخطأ أولًا

قلّل حلّان سابقان تكلفة كل تصيير: جعل صفحات الكيانات ثابتة وتخزين محمّلات JSON مؤقتًا. لكنهما لم يقللا عدد الاستدعاءات.

التصيير الرخيص إذا تكرر مع كل طلب من كل زاحف يظل مكلفًا.

## الحل كان إعدادًا واحدًا

كانت اللغة موجودة أصلًا في عنوان URL، ولم يكن ملف الارتباط يُقرأ. أدى تعطيله إلى استعادة الاستجابات العامة، ثم أضفنا فحصًا دوريًا لترويسات التخزين المؤقت.

عندما يستهلك تطبيق «ثابت» وقت الخادم، افحص قابلية التخزين قبل سرعة التصيير. افهم عدد مرات التنفيذ قبل تحسين تكلفة المرة الواحدة.
